# D v6：同一待办任务的模型与时间综合推荐

## 已实现的行为

入口：河边 → 使用历史与报告 → 待办任务推荐 → 为一个待办任务综合推荐模型与时间。

用户选择可比任务组，填写截止时间、任务优先级、是否允许等待和可选费用上限，再确认各模型当前可访问及预算。页面同时给出推荐模型、建议开始时间（或额度恢复后的重新检查时间）、含安全余量的预计完成时间、最晚开始参考、历史消耗、质量证据和其他模型被排除的原因。修改条件后立即重新计算。

月报示意内有独立的 6 条模拟任务：普通任务倾向节约模型，紧急任务倾向快速模型；收紧截止时间会排除较慢的模型。示意记录与预算不写入真实账本。

## v5 的新增约束

- 评价来自独立追加日志的最新版本；“无法判断”撤销该任务作为达标证据的资格。详见 D_TASK_LEDGER.md。
- 可填写任务需要的图片理解、工具调用、完整上下文 Token。模型能力由用户确认或适配器提供；不按模型名猜测。指定需求不满足时排除；未填上下文需求会说明容量尚未验证。
- “指定模型”会排除其他候选，但不会绕过能力、质量、期限或资源约束；指定模型失去样本时不会偷偷改选其他模型。
- 用户主动开启“允许价格估算”并为模型配置单价后，可按历史实际 Token 与当前单价生成费用参考。输入包含缓存，计算时减去缓存再按对应单价计费，不重复相加。
- 价格必须有公开来源网址、版本、生效时间、有效期、币种及非缓存输入 / 缓存输入 / 输出单价，用户确认计费范围完整。缓存数量未知且缓存价不同、价格无效或有效期不能覆盖预计执行区间时拒绝该估算方案。暂不支持图片额外计费及未声明的其他收费项目。
- 当前单价估算与历史实报明确区分；允许两种依据作参考比较时显示提示。旧的 price-estimate 金额不会被当作实报。修改当前价格不修改历史费用。
- v6 按来源 / 账号保存模型能力、上下文容量、偏好和价格配置；可用余额、预计额度、访问确认不保存。重新打开时必须重新确认资源。价格网址不自动访问，也不代表已替用户核验当前官方价格。

## 决策顺序

1. 只取当前来源、当前账号、独立查询的最近 30 或 90 天结束任务；不受周月报区间影响。未来记录、重复记录不增加样本。冲突记录直接报错。
2. 只比较相同 category、comparisonKey、评价方法和 rubricVersion，且单个任务只使用一个模型的记录。默认保守策略：每模型至少 3 个已评价任务，全部成功且 accepted=true。v6 可手动改选近期策略：只看最近 10 个同组已评价任务，至少 5 个、成功达标比例至少 80%，且最近一次必须成功达标；失败记录保留并计入比例。近期策略的时间与费用只参考其中成功达标任务，明确不含未来失败重做成本。未评价记录不视作达标，多模型任务不直接归功于其中一个模型。
3. 用历史耗时第 80 百分位估计耗时，另加 max(10 分钟, 耗时的 20%) 余量。现在开始仍来不及的候选排除。
4. 必须有完整的实际 Token、服务商实报费用，或独占观测的任务额度证据。Token 包含重试，缓存输入不重复计算。默认仅在全部调用均为 provider-reported 且同币种时形成历史费用参考；主动开启价格估算后，也可用完整实际 Token 与有效单价计算当前价格估计。price-estimate 不作为实报费用基准。
5. 可选任务费用上限需要同币种费用估计。模型当前可用预算也需覆盖该估计。估计不能保证最终费用不超限，执行器仍须在执行中控制开销。
6. 当前可用状态必须已启用、同账号、确认时间不在未来且距今不超过 5 分钟。资源信息重复或缺失时不给出确定方案。
7. 额度模式检查全部声明窗口，Codex 必须同时有 short 和 weekly。不足时，紧急任务或不允许等待的任务直接排除；其他任务取不足窗口最晚恢复时间，并检查加上耗时及余量后能否赶上截止时间。
8. 紧急 / 高优先级：先选当前可行候选，再优先较早完成，随后比较可比费用和模型偏好。普通 / 低优先级：所有可行候选均有同币种费用时优先较低费用，否则不判定谁更省，改按完成时间排序。其他指标相同才用用户模型偏好，数值越小越优先。

三个样本、P80 和缓冲时间都是首版产品规则，尚非统计保证。质量来自用户或执行器评价，系统不自行鉴定输出正确性。全部已评价样本达标也不代表全部未评价任务达标；存在选择偏差时不能外推。

## 当前资源如何获取

- 普通模型：用户确认自己可访问该模型，并填写当前可用费用预算；不是自动查询所有服务商余额。
- provider 为 codex 的任务记录可选择当前 Codex 额度。页面取 A 模块当前账号的新快照，同时要求手动确认模型可访问、填写本次短周期和周额度预计百分点。
- Codex 订阅额度不用于判断其他 API 模型的余额，不把百分点换成 Token 或金额。预计百分点是用户预算，未知必须留空。
- 手动确认有效期为 5 分钟；修改资源参数后要重新确认。报告刷新会保留输入；切换账号或真实 / 示意模式会重置；切换周月报保留待办条件，避免把旧确认带到其他范围。
- 等待方案是 recheck：到时重新读取资源、重新计算，不能当成已经预订成功或确定会自动运行。

## 执行模块接入

纯函数位于 src/reports/unifiedPlanner.ts：

```ts
recommendTaskPlan(pendingTask, taskRecords, modelCapacities, now)
```

pendingTask 使用 PendingPlanTask：来源与匿名 scopeId、category、comparisonKey、method、rubricVersion、deadlineAt（ISO）、priority（urgent/high/normal/low）、allowWait、budget（null 或 currency + amount）。模型名从历史记录和资源候选提取，不按名称推断能力。

modelCapacities 使用 ModelCapacity：同一作用域、provider、model、enabled、preference（0–999 整数）、checkedAt、basis（user-confirmed/provider-reported）和 capacity。capacity 二选一：

```ts
{ kind: 'money', currency: 'USD', remaining: 10 }
// 或
{ kind: 'quota', windows: [
  { key: 'short', remaining: 50, needed: 10, resetAt: '2026-10-22T06:00:00.000Z' },
  { key: 'weekly', remaining: 60, needed: 5, resetAt: '2026-10-25T06:00:00.000Z' }
] }
```

示例时间仅说明结构，调用时必须使用实际当前数据。provider-reported 只供真实适配器使用，不应把手填值标成服务商上报。

新增参数：PendingPlanTask 可带 requirements（images/tools/contextTokens）、qualityPolicy（strict / recent，默认 strict）、allowEstimatedCost、lockedModel（provider/model）；ModelCapacity 可带 capabilities（images/tools/contextTokens）与 price（ModelPrice，定义在 plannerEvidence.ts）。cost 返回 basis=historical-reported 或 current-price-estimate；估算还返回 priceVersion / priceSource。旧调用不提供新增字段仍兼容，并提示未验证上下文容量。

返回 UnifiedPlan：ready / recheck / unavailable / invalid；包含 recommendation、alternatives、explanation、warnings。每个候选都有时间、耗时与缓冲、Token / 费用参考、样本量、关联任务 ID、理由与局限。调用方应展示说明，禁止只取 model 字段丢弃条件。

执行器通过 TaskExecutionRecorder.finish(status, quota, evaluation) 写入完成记录；参数口径见 D_TASK_LEDGER.md。当前界面可手工输入待办条件，B 后续可以直接传入其任务期限、优先级和匹配的评价组，不需要重写推荐规则。

## 边界与验收

这是一套单任务推荐功能，已包含规则和界面；不会调用收费模型、预留余额、创建队列或定时执行。多个待办同时执行时，执行器必须管理资源预留与并发；不能让多个任务重复占用同一份预算。当前没有声称服务商按时段动态降价，因此不会编造低价时间。

初版 13 项自动测试覆盖优先级、紧截止时间、质量失败 / 少样本、预算不足、估算与实报费用区别、双窗口等待、过期 / 不同账号额度、未来 / 过期 / 重复历史、不同币种、未知消耗、非法输入和模型偏好。页面验收覆盖普通与紧急选择变化、截止冲突、费用上限、刷新保留输入和独立示意不写入真实账本。

最新验收见 D_V5_IMPROVEMENTS.md；v5 包括价格有效期、缓存拆分、明确指定模型、能力筛选与独立历史的测试。


v6 增加冷启动使用引导，不为无历史新模型编造质量证据。小规模试用必须由用户在实际执行模块手动选择、限制预算并评价；本页面不代为调用。推荐策略选择本次有效，不默认放宽质量规则。最新验收与操作见 D_V6_RELIABILITY.md。
