### DeepSeek Prompt 优化与任务拆解（可选）

任务分析在未配置网络服务时仍会使用本地规则生成 Prompt 和任务方案。要启用 DeepSeek Prompt 优化及任务拆解，分别启动团队服务和桌面端：

```powershell
# 终端一：仅在服务端设置密钥，不要写入源码或提交到 Git
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
$env:RATE_LIMIT_HASH_SECRET="至少 32 个字符的随机字符串"
pnpm dev:prompt-api

# 终端二：桌面端只需要非敏感的服务地址
$env:PETCAST_AI_API_URL="http://127.0.0.1:8787"
pnpm dev
```

本机验证可在被 Git 忽略的 `.env.local` 中设置 `DEEPSEEK_API_KEY`，再运行 `pnpm dev:ai`。服务只接收 Prompt、本地分析结果、执行 Provider 的公开能力，以及文件名、MIME、大小；不读取或上传附件内容、工作区路径、账号或额度。API Key 不会进入 React 页面、构建产物或 EXE；调用失败、超时、限流或返回非法任务图时自动回退本地规则。`PETCAST_PROMPT_API_URL` 继续作为旧配置兼容项。公网部署必须使用 HTTPS、持久化限流目录和服务端消费上限。

### DeepSeek 公网服务与公开安装包

P2.9C 提供通用 Docker 服务和公开安装包地址内置流程；P2.10 增加 Render Blueprint、公网验收命令和 `0.1.3-beta.1` 团队包流程。部署、HTTPS、持久化限流及 `dist:win:public` 使用方式见 [DeepSeek 规划服务部署说明](docs/B_P29C_DEPLOYMENT.md)，实际 Render 与异机验收记录见 [P2.10 验收说明](docs/B_P210_ACCEPTANCE.md)。远程服务异常时继续安全回退本地规则。

上游连接问题可先执行零推理诊断：

```powershell
pnpm diagnose:deepseek
```

该命令只调用 DeepSeek 的 `/models` 接口，检查 Key、余额、限流、服务状态和模型可用性，不发送任务 Prompt，也不产生规划推理。脱敏结果写入被 Git 忽略的 `work/deepseek-upstream-diagnostic.json`。只有诊断结果为 `READY` 后，才应显式启用 `pnpm test:task-planning:live`；真实验收每次最多发送一次规划请求且不会自动重试。

### ChatGPT 连接与 Codex 自动执行（试点）

桌面版任务分析页可通过 **Continue with ChatGPT** 在系统浏览器中完成授权。PetCast 使用 PKCE 和回环回调，访问凭据仅在 Electron 主进程中使用，并通过操作系统安全存储加密；React 页面、任务存档和执行日志不会收到 Token。

- 只有已授权工作区内的 `coding` / `testing` 任务可进入 Codex 自动执行；其他 AI 仍使用人工复制 Prompt。
- Codex 始终先在隔离副本中工作，用户审查 diff 并明确确认后才能写回原项目。
- 断开连接时会尝试远程撤销可续期会话，并清除本机凭据；页面也可打开 ChatGPT 用量设置。
- 开发者如需回退到旧的本机 Codex 登录复用，可显式设置 `PETCAST_EXPERIMENTAL_LOCAL_CODEX_AUTH=1`；公开版默认禁用此回退。

该接入按 OpenAI 公开的 Sign in with ChatGPT 协议和 app-server `ACCESS_TOKEN` 方式实现。发布前仍需完成应用注册、隐私政策、异机登录以及安装包验收。

## B：任务分析与 Prompt 优化

负责分析用户输入的任务、Prompt 和文件元信息，并生成可人工分发给不同 AI 的任务方案。点击主窗口顶部“任务分析”进入。

- 规则分析结合 Prompt 与文件名称、类型、大小等元信息，判断任务类型与复杂度，估算 Token 区间，并给出串行 / 并行建议。
- Prompt 默认由本地规则优化；配置团队服务后可使用 DeepSeek 优化，失败、超时或限流时仍返回本地结果。
- `LocalBrainProvider` 会生成经过严格 DAG 校验的 `TaskPlan`，按编程、研究、写作和测试能力推荐 Codex、DeepSeek、豆包或本地规则。
- 任务拆解大脑与子任务执行 AI 已分离：默认使用离线本地规则；配置团队服务后可选择 DeepSeek 生成经过严格校验的任务图，失败时明确记录原因并安全回退本地规则。
- 人工任务卡支持逐卡切换 AI、复制专属 Prompt、粘贴外部结果、逐项验收、依赖解锁和执行前人工调整依赖。
- 最近一次任务会话独立保存；全部任务与最终验收通过后，可复制或下载不含完整 AI 正文的 Markdown 摘要报告。
- 浏览器附件只使用名称、MIME 和大小，不读取文件正文；桌面工作区只在用户授权后向隔离副本复制受限 UTF-8 文本。
- 当前仅 Codex 编程/测试任务支持受限自动执行；DeepSeek、豆包和其他任务仍需人工复制。启发式 Token 估算不作为账单，真实 Codex 执行按 D 接口记录供应商上报 Token，费用未知时保持 `null`。
- 核心实现位于 `src/task-analysis/`、`src/orchestration/` 和 `src/components/TaskAnalysisPanel.tsx`。

验收时可输入包含多个独立及依赖子任务的 Prompt，检查 AI 推荐、并行根任务、依赖解锁、会话恢复和报告导出；执行 `pnpm test:task-ui` 可在无网络、无真实模型调用的 Electron fixture 中验证完整 B 模块闭环。详细矩阵见 [P2.7 端到端验收](docs/B_P27_ACCEPTANCE.md)。

完整职责、接口和阶段记录见 [团队开发指南](TEAM_DEVELOPMENT_GUIDE.md) 的 B 模块章节。

## D：历史记录与周月报

点击“河边”，再点击右侧“使用历史与报告”。

- 周报可选开始与结束星期（含止日，可跨周）；默认周一至周日。月报默认自然月，可选月份或手动修改起止日期。按所选时区计算，当前区间截至现在。
- 只保存 fresh 额度；通常每 3 分钟记录一次，压力边界、窗口变化或回升补记。真实 / 模拟 / 账号隔离，重启保留。
- 每日消耗图、24 小时时段图、平均 / 峰值速度、低额度次数与持续时长；月报增加月内分段趋势。缺失不算零，不把额度百分点换算为 Token 或金额。
- 上期比较按对应已过去时长，并检查两期覆盖时长与时段分布。习惯描述需至少 3 个有效日期、6 小时记录；称号附依据，模拟称号不计入真实数据。
- 任务账本提供完成耗时、Token、可归因额度和费用的平均 / 最低 / 最高，逐任务与逐调用追溯，以及高 Token 任务线索。未知数据不记零；币种、上报与估算金额分开。
- 任务建议已自动接入账本：重试排查、输入输出范围、同类变化、满足质量与实报费用条件的模型试用建议；可填写待执行任务预算 / 截止时间，结合当前额度评估是否等待。规则见 [任务建议说明](docs/D_TASK_ADVICE.md)。
- 同一待办任务可综合推荐模型和时间：质量 / 实际消耗 / 期限 / 当前资源共同筛选，普通与紧急任务使用不同排序，显示未选模型的原因。v5 独立查询近 30 / 90 天历史，支持事后评价、能力筛选、指定模型及主动开启的当前单价估算。见 [综合推荐说明](docs/D_UNIFIED_PLAN.md)。
- Codex 编程/测试执行器已通过 `TaskExecutionRecorder` 接入任务账本：调用前先持久化执行意图，完成后记录服务商上报 Token，费用未知时保持 `null`。人工复制任务不会伪造真实执行统计。
- 桌面独立文件存储、浏览器独立 localStorage；额度历史保留 90 天 / 每作用域 100,000 条，常规 3 分钟采样可覆盖 90 天（约 43,200 条）。浏览器仍受站点存储容量限制；异常密集记录可能触发上限。
- 任务账本保留 180 天 / 每作用域 10,000 个结束任务。额度历史和任务记录分别确认清除，其他账号与游戏存档不受影响。损坏文件不会被静默覆盖。
- 独立“月报示意”提供模拟额度、称号与任务账本，绝不写入真实历史。

验证：`npm run test:history-ui`（独立临时目录和测试账号，无需网络）。详见 [D 模块说明](docs/D_USAGE_HISTORY.md) 和 [任务执行器接入](docs/D_TASK_LEDGER.md)。

## 下一阶段计划（2026-10-28 起）

以下为开发目标，不代表已实现。沿用上文 A/B/C/D 已有工作，不重新开发已有五宠、Codex 读取和周月报基础。新增功能与缺陷分开跟踪。

目标：用户输入需求、选择主控 AI，由主控拆解、分配、监督、验收上一步并衔接下一步。PetCast 校验指令，优先操作用户授权的 AI 软件，API 作为用户允许的备用。完成后可按用户选择的方向迭代成果并保存版本。

### A：双平台资源读取与软件适配
- 基于现有 Codex 读取增加第二个平台；先确认真实测试账号与查询能力。
- 统一平台、匿名账号作用域、资源类型、单位、数值、采样时间和新鲜度。Codex 5 小时与周额度不算两个平台；余额、额度百分比和剩余 Token 分开，余额不能冒充 Token。
- 在 C 的通用操作能力上适配两个 AI 软件：发送、上传、生成状态识别、回答及文件回收、登录/限流/超时错误。
- 用户可新增 AI 配置、能力与偏好；已有适配器通过检测才启用自动操作，其他标为待适配或人工模式。维护用户允许的 API 备用连接。
- 验收：两个平台真实数值与官方同账号、同配额组、相近时间对照；账号切换、断网、重置不串数据；两个软件完成真实收发。发送状态不明时不自动重复。记录支持版本和资源类型，凭据不进入日志。

### B：主控与自动任务编排
- 基于现有规划和任务会话，让指定主控接收需求、AI 能力、资源和偏好，返回任务编号、执行者、依赖、成果及验收要求。
- 主控决定分配；PetCast 校验权限、依赖和能力，失败反馈主控调整。
- 将前置成果及 D 的检查证据交给主控，由其决定通过、修复、切换或请求补充；通过后自动衔接。
- 支持换主控、换执行者、暂停恢复和有限迭代；保留原始目标、计划、成果及待办，避免重复执行。
- 验收：至少三个依赖任务、两个执行 AI，无需逐步复制粘贴；故意不合格成果触发修复；暂停/重启/换主控后继续；API 与软件路径分别记录，API 通过不算软件操作通过。

### C：通用操作、宠物与产品交付
- 提供窗口/页面定位、输入、点击、文件选择和操作后核对；A 定义具体软件流程。
- 提供互斥、超时、停止及人工接管，窗口变化先核对目标。
- 整合主控选择、AI 管理、调度偏好、任务进度与成果入口。
- 在已有五宠基础上建议新增两款可切换形象，完善待机、执行、等待用户、完成反馈；允许复用动作，缺失动作回退。
- 打包并组织异机安装、升级与存档验收。
- 验收：不输入错误窗口，随时可停止；新增宠物选择重启保留、旧玩法正常；状态对应真实任务；另一台 Windows 完整运行。
- 控制范围：首期一种 Windows 环境，不新增大型玩法；各组自行完成模块界面和测试，C 不承担所有业务收尾。

### D：周月报、习惯与成果检查
- 基于现有历史和账本接入两平台，按账号、平台、资源类型隔离。
- 整理活跃日期、常用时段、消耗高峰、低额度、常用 AI、任务类型、失败重试和切换习惯；同时记录主控规划与执行。
- 区分运行与人工等待时间；实际 Token/费用可获取才展示。额度百分比不换算 Token，跨平台百分比不求和，缺失不记零。
- 首页突出概况、关键变化、少量行动建议；细节展开，保留周区间及自然月/手动日期。称号和习惯附依据，不凭使用间隔推断分心。
- 检查内容、文件及适用测试，给主控提供证据；归档交接、最终成果和迭代版本，支持导出、比较和回退。
- 验收：实际记录与报告逐项一致；至少三类有依据习惯，样本不足不强行结论；识别缺失成果并反馈；日期边界及真实/模拟隔离正常；成果找得到。

### 设置中的 AI 管理与调度偏好
支持主控决定、软件默认排序、用户自定义三种模式；按编程、写作、检索、分析等类型排序，区分“优先使用”与“仅使用”。当前任务明确指定优先且必须满足强制限制；不满足时询问。
可设置失败切换、主控调整软偏好、API 备用授权与预算。修改默认仅影响未开始任务。用户填写属性与实测能力分开；新增配置不自动获得操作能力。
A 管配置和状态，B 落实调度，C 做公共设置界面，D 记录原因及效果。
