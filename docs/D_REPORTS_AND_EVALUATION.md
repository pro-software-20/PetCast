## 报告试用

从主页进入“使用历史与报告”。默认打开“近期”（最近七天），可切换到周报、月报。周月报共用布局，按所选时间统计。展开“使用习惯与任务反馈”中的任务，可以核对实际模型、用时、失败和重试。“平台资源”按账号、平台、资源种类和单位展示期内最近的采样。

用户界面已移除月报示意入口。示意图以独立 PNG 交付，不写入用户账本。

实际成果位于任务分析的最终验收区域。点击“归档当前成果”，之后可以在同一账号的“近期 → 已归档成果”中重新打开。Markdown 导出使用本机下载功能。HTML 预览采用隔离框架。无账号执行的人工任务归入本机范围。

## 组间接口

- A 可调用 appendResourceSamples(scope, samples) 或导出 v1 JSON 供报告导入。界面提供当前作用域对应的 JSON 模板。账号字段使用别名，时间为 UTC ISO 字符串，百分比、Token 和货币余额分别使用 quota-percent、tokens、balance。Codex 历史直接读取现有有效采样；第二平台需由适配器提供真实值。
- B 的任务账本支持可选调用阶段 stage（planning 或 execution）及实测人工等待 humanWaitMs。旧账本和缺少计量的调用可继续读取。调用时间以区间并集计算。没有人工等待事件的任务显示“未记录”。
- B 的最新自动派发进入待验收后，任务卡提供“成果检查证据”。D 从经校验的摘要与逐项证据生成 accepted、revise 或 unknown，交给 B 决策接口并保存到该会话。失败项建议返工，证据不足转人工核对。文件选择只核对所选文件的名称及非空大小。当前策略保留人工确认。
- 真实任务链的验收依赖 A 的运行适配器。跨模块测试用受控执行结果覆盖失败退回、下一次尝试通过及决策持久化。

## B 组接入入口

App.tsx 把 TaskEvidenceAdapter 注入 TaskAnalysisPanel。任务进入待验收后，B 的 requestTaskEvaluation 构造请求并调用 evaluate(request, signal)，再由现有协调逻辑保存建议。可选 evidence 字段支持逐项补充证据（reference 为 check:0、check:1 等，按验收项顺序）。同一次派发沿用 B 的稳定评价 ID。缺少依据时返回 unknown，人工策略下仍由用户确认。联调时验证一次失败退回和下一次尝试通过。

验证命令：node --test tests/d-workspace.test.mjs tests/task-evaluation*.test.mjs

## 本轮优化

- 评价规则升级为 petcast-d-2。同名验收标准按位置匹配，保留失败项的具体说明，避免第二项失败被第一项通过覆盖。接口字段不变，已保存的旧评价继续由 B 复用。
- 任务建议按失败、重试、用量缺失分别触发，显示依据和相关任务。无触发条件不生成凑数建议。重试消耗只累计实测调用，零 Token 与未返回用量分开。
- 规划、执行、未分类调用分别列出次数、已上报 Token 和计量覆盖。未分类数据不自动归入执行。
- 展示多 AI 参与任务数，按平台和模型组合去重。它不表示故障切换次数，也不据此判断模型质量。

## 验收与剩余工作

1. 使用历史与报告 → 近期/周报/月报 → 使用习惯与任务反馈：核对规划与执行用量、建议数字和相关任务。
2. 同名验收项分别设为通过、失败并提供逐项依据：评价应返回 revise，显示第二项的失败说明。
3. 运行 `node --test tests/d-report-improvements.test.mjs tests/task-coordination-d-e2e.test.mjs`，验证新规则及 B/D 调用链。

本轮生产构建和全部 500 项契约测试通过。真实外部 AI 派发仍等待 A 的统一执行适配器，参见 B_P34B_D_INTEGRATION_ACCEPTANCE.md。两平台真实资源、规划阶段计量、人工等待事件需要各数据生产方回传，D 不补造缺失数据。文件内容的自动检查与适用测试执行尚未接入，当前评价使用验收状态与关联证据。
