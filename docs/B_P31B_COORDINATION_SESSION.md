# B-P3.1B：协调状态接入任务会话

## 目标

P3.1B 在 P3.1A 的持久化协调状态与现有 `TaskSessionV1` 之间增加安全桥接层。桥接层只负责把已经发生的 A 组执行事实写回任务会话，不创建轮询器、不调用真实适配器，也不自动验收任务。

## 数据来源

- `TaskCoordinationStateV1` 是恢复时的事实来源。
- `TaskCoordinationEffect[]` 只用于即时提示和关联校验；丢失 effects 后仍可依靠持久化状态恢复。
- `TaskSessionV1` 继续保持 `schemaVersion: 1`，不保存凭据、绝对路径、供应商原始响应或协调执行引用。

## 状态映射

| 协调状态 | 任务会话状态 | 说明 |
| --- | --- | --- |
| `dispatching` | 保持 `ready` | 尚无可靠收据，不伪造已运行状态 |
| `queued` / `running` | `running` | 尝试次数只增加一次 |
| `needs-input` | `needs-input` | 等待用户补充信息，独立任务不受影响 |
| `completed` | `review` | 写入结构化结果，仍需人工验收 |
| `failed` | `failed` | 保存安全错误说明 |
| `cancelled` | `cancelled` | 不自动重试 |
| `unknown` | `needs-input` | 要求人工核对，禁止重派 |

## 安全与幂等规则

- 会话、计划、任务、Provider、尝试次数、`dispatchId`、执行引用必须严格关联。
- 结果的任务 ID、Provider、验收项标签和安全相对路径必须与当前任务一致。
- 相同协调记录重复应用是安全 no-op，不重复增加尝试次数。
- 旧尝试和迟到终态不能覆盖新尝试或已保存结果。
- 如果会话保存失败，返回原会话；下次启动仍可根据协调状态重新恢复。
- `completed` 永远不会直接变成 `done`，人工验收和未来受信 D 评价仍是独立步骤。

## 后续接入

P3.1C 才会增加页面控制、持续协调、暂停恢复和真实 A 组适配器联调。接入时应先运行一次协调周期，再调用本桥接层，最后保存通过严格校验的任务会话。
