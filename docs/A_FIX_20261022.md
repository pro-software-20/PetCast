## 组员反馈：安装后正常，原差异根因未确认

截图中 PetCast 为 5h 剩余 76%、周剩余 94%；另一个客户端为 95%、99%。两边都显示剩余比例，不能用“已用 / 剩余看反”解释。PetCast 标为真实额度，也不能简单归因于模拟模式。

当前主看板按 `100 - usedPercent` 换算 `codex` 配额组，不通过 AI 估算。该公式符合官方字段含义，但只有两边登录配置、工作区、配额组及采样状态一致时，数值才具有直接可比性。2026-10-22 用户转述组员“安装后就没问题了”，记录为异机正常反馈。没有安装前后的版本与接口对照证据，无法确定此前差异根因；本次没有硬编码截图数值或擅自改读另一个配额组。

## 新增的核对入口

1. 更新并重新构建 / 启动 PetCast，打开“河边”，在右侧“额度数据”中点击“重新读取”。
2. 展开“账号与额度来源核对”。查看脱敏账号、套餐、程序来源、是否使用自定义 CODEX_HOME，以及主看板使用的配额组。
3. 对照另一个客户端的当前登录账号、5h / 周剩余及重置时间。详情列出服务端返回的其他配额组，各组独立显示；不能为了匹配数字自行认定哪组属于某模型。
4. 如果账号或套餐不同，先在 PetCast 实际读取的 Codex 登录配置中核对登录。PetCast 不自动登录、退出或切换其他应用的账号。
5. 如果账号相符但其他组的值与客户端一致，保留该组名称和时间用于进一步核实；主看板暂未提供配额组切换，D 的历史仍仅记录主看板组。
6. 如果来源均一致但刷新后仍不同，保留两边同一时刻的百分比、重置时间和版本号进一步排查，不把差异当作已解决。

可选开发诊断（先执行项目构建）：

```powershell
node scripts/check-codex-usage.mjs --details
```

默认诊断输出仍只有额度和时间；`--details` 才输出脱敏来源详情。不要发送登录文件、Token 或 Cookie。页面详情在 stale 时明确标记是“上次成功读取的来源”。诊断字段不写入历史样本或游戏存档。

## 测试及边界

截至本轮 r2，204 项自动测试及生产构建通过（前一轮为 197 项）。本轮新增 7 项覆盖查找超时 / 取消、请求 ID 碰撞、非法响应、休眠后旧快照、重复旧采样和时钟回退。前一轮用例还覆盖两窗口约束、重置到点、未来时间取整、建议依据、不同配额组独立显示、诊断脱敏及可变数据隔离。多组 76/94 与 95/99 的测试为人工构造的回归样例，不是组员电脑的实际接口响应。

隐藏窗口额度页面验收、历史报告页面验收（含 B 任务分析入口）及本机真实 Codex → IPC → 页面 → 历史保存通路均通过。页面用例验证来源详情同时展示不同组的值、不显示完整邮箱，以及 focus / online 事件触发重新读取。休眠与时钟变化使用可控时钟进行回归，不等同于实际机器睡眠测试。

仍需另一台电脑完成休眠、断网、换账号和安装升级的完整验收。当前仓库没有最终 EXE 打包配置；用户所说“安装后正常”不等于本仓库已完成安装包交付。其他窗口组合，以及不提供工作区 ID 时的同邮箱多工作区隔离，尚不能宣称已完成。来源核对不能证明服务商数据毫无延迟，90 秒只是本地快照保护阈值。
