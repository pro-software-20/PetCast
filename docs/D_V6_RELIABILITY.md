# PetCast D v6：执行记录可靠性、配置保存与冷启动

交付日期：2026-10-22。包含 v5 全部功能。本轮落实上次检查的三个高优先级事项；源码在本地，未推送 GitHub。

## 本轮解决了什么

| 问题 | 改进后的行为 |
| --- | --- |
| 整个任务结束前，调用记录仅在内存 | 调用前持久化发起记录，调用返回后立即保存状态与计量；日志写入失败阻止继续发起新调用 |
| 重启后不知道哪些调用已执行 | 报告新增“执行恢复检查”，按账号列出未结束任务、已保存调用、结果待核实调用；不自动重跑 |
| 已结束任务未写入报告 | 结束日志先于报告保存；点击“补存已结束任务”幂等补存，冲突不覆盖，无新增供应商调用 |
| 模型参数每次重新填写 | 按来源和匿名账号保存能力、上下文、偏好、价格参数；重新打开自动恢复 |
| 旧余额可能被当作当前可用资源 | 余额、预计额度和访问确认不保存，重新打开必须重新填写、确认；价格仍受有效期检查 |
| 新用户缺少可比历史 | 页面提供小规模手动试用与评价积累引导，明确不生成无证据的质量 / 省钱承诺 |
| 一次早期失败长期挡住模型 | 保守规则仍默认启用；用户可改选“近期表现”：最近 10 个已评价任务，至少 5 个，成功达标比例 ≥80%，最近一次达标。保留旧失败记录、显示依据与局限 |

近期策略只对成功达标任务估计时间 / 费用，明确提示未计入未来失败重做开销。门槛是首版产品规则，不是统计置信度。没有历史的模型仍不能获得数据支持的自动推荐；引导试用不等于系统已经执行试用。

## 用户怎么测试

1. 启动后进入“河边 → 使用历史与报告”。展开待办任务推荐，可查看“新用户 / 证据不足时怎么选”。
2. 有历史任务时，为模型填写上下文容量和偏好。关闭、重开程序，确认配置保留，而可用预算为空、模型未确认可访问。
3. 如果采用可选近期策略，检查每个模型的样本数、成功达标数及排除理由；默认保守规则不变。
4. 执行模块接入后，在报告“执行恢复检查”核对未结束记录。没有执行日志时显示没有未结束任务，不用模拟数据冒充真实任务。
5. 对已有完整结束日志但报告缺失的任务，点击“补存已结束任务”。它只写入历史，不调用模型。

独立“月报示意”仍不持久化模型配置或任务记录。不要为制造恢复场景而直接中断真实收费任务；自动测试已用模拟供应商覆盖这些边界。

## 存储与准确边界

- 结束任务账本仍为 version=2；新增独立 version=1 执行日志。旧版程序不能理解执行日志，勿降级后写同一个数据目录。
- 若崩溃发生在供应商已经执行、但 complete 尚未保存的间隙，只能知道“已记录发起，结果待核实”。不能承诺任何时刻中断都能恢复真实账单或结果正文。远端请求 ID、供应商查询与幂等仍需执行适配器接入。
- 未结束记录也可能仍在运行。页面不会擅自判为失败、自动重新调用或把未知费用记作零；未结束任务不会计入已完成任务统计。
- 执行日志最多 10,000 个任务；桌面日志上限 64 MB，浏览器还受站点容量约束。日志不自动淘汰待核实记录；容量不足阻止新调用。长期数据库化、索引与完整备份恢复尚未实现。
- 清除当前账号任务会同时删除评价及执行恢复副本，需先停任务；其他账号、额度历史和游戏存档不受影响。跨文件清除并非原子事务，失败时必须核对后重试。
- 本机模型设置不包含 API 密钥；价格网址只是记录来源，不自动访问或验证。
