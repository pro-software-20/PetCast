# B-P3.8B：桌面 DeepSeek 与 D 评价受控联调

## 目标与边界

本阶段验证已经接入桌面端的 A 组 DeepSeek 执行桥，能够安全经过 B 的协调、恢复和 D 的证据评价流程：

```text
用户确认 → DeepSeek 派发 → 结果进入 review → D 评价建议 → 用户决定
```

默认发行版仍不会自动启动、自动恢复或自动重试外部执行。D 的建议也不会自动完成、退回或重新派发任务。

## 零网络联调基线

以下命令使用桌面桥接 fixture 和真实 `TaskEvidenceAdapter`，不会读取 `.env.local`、调用网络或消耗模型额度：

```powershell
pnpm test:desktop-deepseek-d-e2e
```

该验收覆盖：

- 首次启动必须经过队列确认，确认前没有 DeepSeek 调用；
- 同一个派发只调用一次，完成后只进入 `review`；
- 重建协调器后只读恢复完成记录，保持暂停且不重新派发或查询；
- D 只收到结果摘要、验收状态和显式证据，不收到完整模型输出、凭据、绝对路径或额度信息；
- 已持久化的 D 评价会复用，不会再次调用评价器；
- 受信评价即使建议完成，任务仍保持 `review`，必须由用户确认。

## 本机真实验收

真实调用只在用户明确确认自动协调后发生。优先使用一个已经由 DeepSeek 完成、且仍处于 `review` 的任务：这一步不需要再次派发模型请求。

1. 关闭并重新打开桌面应用，进入任务分析页面。
2. 确认自动协调状态为“已暂停”，并在对应任务卡看到恢复的派发短标识与完成状态。
3. 点击“请求评价”，检查 D 评价区域只显示安全摘要、逐项验证、规则版本、证据摘要和建议动作。
4. 刷新页面后再次打开同一任务，确认评价记录仍存在；再次请求时应复用评价，不能重新调用 D。
5. 只有在用户点击“按建议确认完成”或现有人工验收按钮后，任务才会变为完成。

如不存在已完成的 DeepSeek 任务，可按 `B_P38A_DEEPSEEK_DESKTOP_INTEGRATION.md` 创建一个简短、无文件写入任务。一次验收只允许一个自动任务，并在队列确认页检查 Provider、执行方式和费用提示。

## 异常处理

- 没有 Key、限流、取消、超时或状态未知：不要再次点击启动；按任务卡恢复操作先核对外部执行。
- 应用重启后：默认暂停。先检查已恢复的协调记录，不能通过重新启动来猜测旧调用是否完成。
- D 评价不可用：继续现有人工验收；不要将 D 缺失视作任务失败。
- 不要把 `.env.local`、诊断输出、模型全文或本地认证文件提交到 Git。
