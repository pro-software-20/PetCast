# C 通用软件操作安全层

## 目标

下一阶段需要让 PetCast 在用户授权后操作 Windows 上的 AI 软件。C 先提供与具体软件无关的安全协调层；A 再为已确认的平台实现窗口定位、页面识别、输入、点击、文件选择及结果读取适配器。

首期只支持一种约定的 Windows 环境，不把浏览器、不同版本客户端和未知 AI 软件都当作已经适配。

## 当前实现

`electron/softwareOperationCoordinator.ts` 提供以下边界：

- 同一时刻只允许一个外部软件操作。
- 每个步骤执行前重新核对目标窗口和页面，不复用上一步的窗口判断。
- 每个步骤执行后必须由适配器提供结果核对证据，未经核对不能进入下一步。
- 整个操作有明确超时；超时、用户停止、窗口变化或程序退出时均中断。
- 用户选择人工接管后，当前操作立即停止，新的自动操作保持暂停，直到用户明确恢复。
- 事件只公开操作编号、阶段、步骤序号和安全状态，不公开输入正文、文件内容、窗口句柄或适配器内部结果。
- 适配器返回未知错误时统一转换为安全失败，不把本机路径、窗口信息或内部异常发给页面。

当前实现没有注册 renderer IPC，也没有提供真实点击能力。这样可以在 A 尚未定义目标平台、账号状态、按钮和结果规则时，避免页面构造任意桌面操作。

## A 适配器必须实现

每个已确认的软件适配器需要实现：

1. `parseStep`：只接受该软件允许的固定动作和受限字段。
2. `verifyTarget`：在每一步前重新确认进程、窗口和页面属于预期目标。
3. `executeStep`：响应 `AbortSignal`，停止后不得继续输入、点击或重复提交。
4. `verifyStep`：根据页面实际变化判断成功、失败或状态不明；状态不明时不得自动重试可能收费或重复发送的动作。
5. `stop`：尽力停止仍在进行的输入、上传、生成或等待流程。

具体窗口选择器、页面结构和软件版本兼容由 A 维护，不写入通用协调器。

## 后续接入顺序

1. A 确认首个真实测试平台、Windows 软件版本、账号与可识别页面。
2. A/C 共同定义该平台的固定动作 schema 和脱敏结果证据。
3. C 为协调器注册受限主进程 IPC；preload 只暴露命名方法，不暴露任意点击、坐标或系统句柄。
4. B 使用任务状态调用已登记动作，不直接控制桌面。
5. 界面增加停止与人工接管入口，并把宠物状态绑定到协调器的真实阶段。
6. 使用可丢弃账号与无敏感文件的测试任务完成异机验收。

## 验证

```powershell
pnpm test:contracts
pnpm typecheck
pnpm build
```

契约测试覆盖互斥、逐步目标复核、结果复核、超时、主动停止、人工接管、恢复和窗口变化失败关闭。
