# PetCast D v5 改进与验收说明

交付日期：2026-10-22。基于本地 D v4.1 改进；含此前 D 的全部功能，尚未上传 GitHub。

## 已完成

| 改进 | 现在如何使用 |
| --- | --- |
| 任务完成后补评 / 修订 | 报告 → 逐任务明细 → 评价结果与修订历史。选择达标、需修改、无法判断；保留旧评价，账单不变 |
| 推荐独立使用近期历史 | 报告底部“待办任务推荐”选近 30 / 90 天。显示实际查询范围，切换周报 / 月报保留待办条件，账号与示意模式隔离 |
| 能力筛选与指定模型 | 填图片、工具、上下文需求；确认候选能力。指定模型不能绕过质量、时间和资源约束 |
| 可审计的费用估算 | 主动允许估算后填写单价、来源、版本、生效 / 到期时间和计费口径；按历史实际 Token 计算，清楚标为估算 |
| 更方便查账 | 任务名称 / ID 搜索，模型 / 类别 / 状态过滤，每页 20 个；CSV 导出全部筛选结果，不限当前页 |
| 执行器接入验收 | 已验证调用记录→文件持久化→事后评价→模型与时间推荐；实际供应商调用由 B / 执行器传入 |

当前价格配置是本次推荐输入，不会悄悄重算原有账单。历史调用的 cost 可带 pricing.version/sourceUrl/effectiveAt，页面与导出保留依据。来源网址只记录，不自动打开或核验。图片额外费用、复杂阶梯价格和未声明收费项目不在本版估算支持范围。

## 试用步骤

1. 解压完整源码包，按 README 安装依赖、构建并启动。
2. 河边 → 使用历史与报告 → 月报示意。综合推荐使用 6 条独立模拟任务，可切换优先级 / 截止时间 / 指定模型观察推荐变化。
3. 真实记录由执行器写入或导入本账号 version=1/tasks JSON。没有真实执行数据时，页面明确说明证据不足。
4. 展开任务明细，补充可比任务组和评价标准，保存评价。原始任务不改变；新评价会用于后续建议。修改评价需追加修订，不覆盖历史。
5. 在待办推荐中确认能力和当前预算。需要估算时打开“允许价格估算”，展开模型单价配置；填完再确认当前模型资源。
6. 搜索 / 筛选任务后导出 CSV。日期范围来自当前报告；导出所有筛选页，未知数值留空。

## 与组员接入

- B 的实际调用使用 TaskExecutionRecorder；finish 先保存执行结果。后续质量评价使用 appendTaskEvaluations。推荐前独立查询历史、调用 applyTaskEvaluations 得到派生视图，再传入 recommendTaskPlan。
- 新记录字段和两种费用来源见 D_TASK_LEDGER.md；能力 / 价格结构见 D_UNIFIED_PLAN.md 与 src/reports/plannerEvidence.ts。
- C 合并时保留 Electron 的两个新评价 IPC、preload 方法和 UsageHistoryPanel 中独立推荐区域。主窗口 / frame / 地址校验继续有效。
- 不要把 task-analysis 的 Token 粗估当作服务商实际计量；不要把派生评价视图重新追加为原始任务。

## 数据兼容

任务账本可读 version=1，成功写入时升级 version=2，包含 tasks 和 evaluations。原文件路径及浏览器 key 不变，升级无需用户搬文件。旧版程序不能继续操作升级后的同一任务文件；坏文件保留并报错。清除账号任务同时清除账号评价，不影响额度历史与游戏存档。

每任务最多 1000 次调用（发起前检查）、50 次评价；每批最多 500 条评价；全部评价最多 100,000 条。任务保留周期仍为每账号 / 来源 180 天、10,000 条，淘汰任务时关联评价一并淘汰。报告建议与推荐使用的样本范围会明确展示。
